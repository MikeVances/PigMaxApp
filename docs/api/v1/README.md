# API v1 PigMaxApp — инженерный калькулятор свинарников

Контракт — [`openapi.yaml`](openapi.yaml) (сервер отдаёт его на `GET /api/v1/openapi.yaml`
без ключа), коды — [`errors.md`](errors.md), источники — [`../../sources.md`](../../sources.md).
Инфраструктура перенесена из MINMAXapp: ошибки RFC 7807, `request_id`, журнал вызовов,
ключи и лимиты — тот же формат, что у птичьего калькулятора.

## Сценарии

| Метод | Что считает |
|---|---|
| `POST /ventilation-requirements` | одна группа «сейчас»: уставки, тепло, минимальная вентиляция (max CO₂ / влага / норма), максимум при текущей наружной, отопление, эффективная температура |
| `POST /ventilation-designs` | цикл растущих свиней в корпусе: по дням кривой роста — минимум и отопление при расчётной зиме, летняя вентиляция при расчётном лете; оборудование под худший день (вентиляция, отопление, панели, туннельные вентиляторы в рабочей точке) |
| `GET /climate-designs?latitude&longitude` | расчётная зима 99.6 %, лето 0.4 % (ERA5 / Open-Meteo, 10 лет) — для `climate` проекта |
| `GET /genetics`, `/genetics/{id}` | профили генетики растущих: уставки по весу по фазам, нормы, кривая роста; свои профили пользователя — с `builtin: false` (редактор — на странице проекта, маршруты интерфейса под `WRITE_TOKEN`) |
| `GET /sow-profiles` | профили климата свиноматок |
| `GET /sources`, `/sources/{id}` | что утверждает каждый источник, как применён, ограничения |
| `GET /construction-materials` | λ материалов ограждения (BR 443) |

## Что важно понимать в ответе

- **`setpoints.setpoint_meaning`.** `room_temperature` — держать в помещении.
  `ventilation_start` — с этой температуры растёт вентиляция (голландская таблица);
  отопление на 1.5 °C ниже, это `design_room_temp_c`. Балансы считаются по
  `design_room_temp_c`.
- **`min_ventilation.basis`** — какое из трёх требований определило минимум.
  - `moisture` зимой при сырой оттепели — нормально: таблица PIC этот случай
    не закладывает.
  - `humidity_uncontrollable` — наружный воздух не суше цели.
- **`model.method`** — методика тепла: `cigr2002` (по умолчанию), `brown_brandl_2004`
  (растущие, США), `rd_apk_2012` (норма РФ), `stinn_xin_2014` (свиноматки). Разброс
  между методиками — разные эпохи генетики, а не ошибка. Для подсосных
  `stinn_xin_2014` ближе к реальности: CIGR занижает вдвое.
- **Обогрев гнёзд** (`creep_heat_w_per_pen`) — тепло остаётся в помещении и уменьшает
  отопление. Не задан — в ответе `creep_heat_not_counted`.
- **Летняя цель проекта** — 26 °C (РД-АПК прим. 3), а не зимняя уставка: уставка PIC
  14 °C для 147 кг летом недостижима и не является целью.

## Доступ и лимиты

Как у MINMAXapp: переменная окружения `API_KEYS` (ключи через запятую), заголовок
`X-API-Key`. Без `API_KEYS` доступ открыт (локально и в LAN). Лимиты на ключ в минуту:
расчёты 60, справочники 300, климат 10; сверх — `429` с `Retry-After`. Документация
(`/openapi.yaml`, `/docs`) — без ключа. В журнале (`API_AUDIT_LOG`, по умолчанию
`backend/data/api_audit.jsonl`) — отпечаток ключа `key-xxxxxxxx`, не сам ключ.

Публичная площадка (Render) обязана иметь `API_KEYS`: иначе `/climate-designs`
открыт, и перебор координат тратит квоту Open-Meteo.

Ключ: `python3 -c "import secrets; print(secrets.token_urlsafe(24))"`.
