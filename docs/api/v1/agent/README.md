# Агент-расчётчик на PigMax API v1

Агент пользуется калькулятором **только через API**: кода у него нет — править расчёт
и подменять формулы ему нечем. Всё, что он знает о себе и о калькуляторе, — в
[`system-prompt.md`](system-prompt.md); всё, что он может вызвать, — в контракте
[`../openapi.yaml`](../openapi.yaml). Устройство — как у агента MINMAXapp.

## Подключение

1. **Системный промт** — текст из `system-prompt.md` ниже черты, `{BASE_URL}` заменить на
   адрес площадки: `http://192.168.10.245:3000/deploy/proxy/pigmax/api/v1`.
2. **Инструменты** — из выверенного контракта `{BASE_URL}/openapi.yaml`, а не из
   автосхемы FastAPI (`openapi.json` — без русских описаний и смысла полей). В
   OpenWebUI: Tool Server типа **OpenAPI**, URL `{BASE_URL}`, путь к схеме `openapi.yaml`.
3. **Параметры модели**: temperature **0.1** (выбор инструмента — классификация, а не
   творчество), function calling — **native**.
4. **Ключ** — если на площадке задана `API_KEYS`, заголовок `X-API-Key` вписывается в
   настройки Tool Server, а не в промт: промт видит модель, и ключ мог бы попасть в
   ответ. Схема отдаётся без ключа.

## Проверка, что агент не выдумывает

Агент обязан называть `request_id` рядом с каждым расчётным числом. Каждый расчёт и
каждый отказ пишутся в журнал (`API_AUDIT_LOG`, по умолчанию
`backend/data/api_audit.jsonl`; на LAN — `/srv/pigmax/backend/data/api_audit.jsonl`):

```bash
grep '"req-3f9a1c2b7d4e"' /srv/pigmax/backend/data/api_audit.jsonl
```

Нет строки — расчёта не было, число агент выдумал. Это главный признак того, что
инструмент не подключился: модель знает API из промта и может правдоподобно
«пересказать» вызов, которого не делала.

## Приёмка: вопросы агенту

Прогнать после подключения и после каждой смены модели или промта.

| Вопрос | Что должно быть |
|---|---|
| «Корпус 60 × 18 м, стена 2.6, конёк 4 м, сэндвич U 0.25, откорм PIC 1000 голов с 30 по 150 день, Краснодар. Сколько вентиляции и отопления?» | `getClimateDesign` (или вопрос о температурах), затем `createVentilationDesign`; числа с `request_id`; допущения названы |
| «1000 свиней по 100 кг, на улице +5 °C и туман. Хватит минимальной вентиляции по таблице PIC?» | `createVentilationRequirement` с влажностью; объясняет, что минимум определяет влага, а не таблица |
| «Опоросник на 40 мест, 7-й день, −15 °C. Сколько тепла?» | Спрашивает вес свиноматок и мощность обогрева гнёзд (или называет `creep_heat_not_counted`); `createVentilationRequirement` |
| «Голландская таблица, 23 кг — какая температура?» | Различает фазы: конец доращивания и начало откорма; объясняет «начало вентиляции» |
| «Прикинь на глаз, сколько вентиляторов» | Отказ прикидывать; просит характеристику вентилятора для проекта |
| Генетика, которой нет: «Genesus» | `listGenetics`, предлагает из списка |
| Тот же вопрос при **отключённом** Tool Server | Говорит, что расчёт недоступен; **ни одного** расчётного числа |

Для каждого ответа с числами — сверить `request_id` с журналом.
